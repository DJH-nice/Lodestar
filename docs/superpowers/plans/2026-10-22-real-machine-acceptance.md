## 0. 开工前的三句话

1. **本机托盘图标不渲染。** 状态项在菜单栏里**占着位置**（`x=663 w=34 owner='FSearch'`），
   但 `kCGWindowIsOnscreen=false` —— 系统没把它画出来。已排除时序 / PNG / 模板标志 /
   状态项长度 / NSImage 尺寸 / 主线程自死锁等**全部代码侧嫌疑**；且本机三个渲染信号
   **对所有 app 同时失效**（截图纯黑、连微信都 `onScreen=false`）。
   → **这不是代码问题**，但也**没法在本机证明它没问题** → 只能靠 **A21** 收口。
2. **合成鼠标点击被 TCC 挡**（`-25208`），且当时你正在用机器 → 不做侵入式桌面自动化。
   → 下面凡是要「点一下」的，**都得你来点**。
3. **当前生效的快捷键是 `⌥⇧K`**（不是默认的 `⌥⌘Space`，你自己改过了）。
   → 清单里凡是「按快捷键」，一律指 **`⌥⇧K`**；你若改回默认，就把 ⌥⇧K 换成 ⌥⌘Space。

## 5b. 性能优化（2026-10-22 追加，已完成并实测）

| 场景 | 修前 | 修后 |
|---|---|---|
| **后台常驻**（窗口收起来） | 0.57 ~ 0.70 % | **0.04 %**（安静）/ **0.35 %**（机器上别的程序狂写文件时） |
| **窗口可见**（稳态） | 4.77 % | **0.6 ~ 1.4 %** |

> 「机器上别的程序狂写文件」会把数字抬高一档 —— 那是 **watcher 逐条判断排除规则**的开销
> （FSearch 盯着家目录变化，别的程序写得越勤，要判断的次数就越多）。
> 这是一个**独立的、还没做的**优化点（见文末「遗留」）。

**验收时留意**：窗口收起来之后状态栏不再更新是**正常**的（看不见），
但**窗口一回来，状态栏必须立刻恢复更新** —— 这条要有耐心验一下。

**改了什么**（两处，都是「无谓的周期性工作」）：

1. **窗口看不见时停掉状态轮询** —— 那个 800ms 的 `pollStatus` 每次是一次跨进程 IPC
   （实测约 3.4ms CPU），窗口藏着时用户根本看不见状态栏。
   → Rust 侧把可见性告诉前端（`app-visibility` 事件 + `index_status` 的 `visible` 字段）。
2. **状态栏只在内容真变了时才重画** —— `status.value = s` 每 800ms 换一个新对象，
   Vue 就让状态栏重渲染 → WebKit 重新合成。采样里能直接看到
   `RemoteLayerTreeDrawingArea::updateRendering` 被反复调用。

**顺带修掉的两个真 bug**（都是这次优化暴露出来的）：

| bug | 症状 | 修法 |
|---|---|---|
| **启动竞态** | 前端挂载比窗口 `show()` 早 → 拿到 `visible=false` → 不启动轮询 → **状态栏冻住** | 「上次观测到的可见性」改成**三态**（未观测 / 不可见 / 可见）→ 第一次观测**总是**报一次变化 |
| **恢复只靠事件送达** | 窗口被 `NSRunningApplication.activate()` 显示时，AppKit **不发** `Focused(true)` → 前端收不到「窗口回来了」→ 轮询再也不开 | 看门狗每秒比对一次**真实**可见性，变了就补发事件（兜底，≤1 秒自愈） |

> **验收时留意**：窗口收起来之后，状态栏不再更新是**正常**的（看不见），
> 但**窗口一回来，状态栏必须立刻恢复更新** —— 这条要有耐心验一下。

### ✅ 遗留项已做（2026-10-22 晚）

**watcher 的排除判断在「别的程序狂写文件」时是 CPU 大头** ——
每个文件变化都要问引擎「这个路径会不会被索引」（要连祖先一起查，多次 `stat`）。

**已做两层优化**：

| # | 做了什么 | 效果 |
|---|---|---|
| 1 | **ack 机制**：前端把「我现在认为窗口可见」告诉后端，后端只在「实际 ≠ 认知」时推事件 | Tauri 的事件 = **在 webview 里跑一段 JS**（每次约 7ms CPU，隐藏时每次都要叫醒睡着的 webview）→ 「每秒推一次」白花 0.7 %。改成 ack 后**稳态零 IPC**，且事件丢了能自愈。实测 WebContent 进程从 0.29 % → **0.00 %** |
| 2 | **排除判断的前缀缓存**：记住**最上层**那个被排除的祖先，之后落在它下面的事件一次字符串比较就跳过 | 单次 **53.8 µs → 101 ns（531 倍）**，3000 条真实路径只用 **1 个**缓存条目（`~/.minimax` 一个就罩住全部），且**判断结果逐条一致**（不会漏索引） |

**探针**：`cargo run -p fsearch-core --example exclude_bench -- <路径清单>` →
打印「无缓存 vs 有缓存」的 A/B 对照 + 缓存条目。

> ⚠️ 端到端数字会随**机器负载**浮动（load average 2.9 时实测 0.2~0.25 %，
> 空闲时 0.04 %）—— 量的时候别同时跑 `cargo build`，也别在测量窗口里跑 `sample`。
