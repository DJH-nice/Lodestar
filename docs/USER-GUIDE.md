# Lodestar 使用手册

这是一个 **macOS / Apple Silicon 原生的文件搜索器**，产品名 **Lodestar**。

**这份手册是写给三个月后的自己看的**：忘了某个功能点在哪、忘了搜索语法怎么写，
回来翻这一份就能解决。应用里也能看它 —— 顶部菜单栏 **帮助 → 完整手册**。

> 应用里显示的这一本，就是仓库里的 `docs/USER-GUIDE.md`，构建时整份打进了程序。
> 改了仓库里那份，重新打包后应用里就是新的。

---

## 快速上手

1. **打开应用，搜索框里直接打字** —— 不用按回车，结果会自己出来。
2. **第一次启动要等索引建完**。看右下角状态栏：
   - 还在扫 → 显示「正在扫描索引…」
   - 建好了 → 显示「已索引 N 项」
   - 索引 `$HOME` 大概 8 千多项、不到 1 秒；索引一整块硬盘就会久很多。
3. **只搜一部分目录更快**：标题栏 **设置** → **添加目录…** → 选好 →
   **应用并重建索引**。
4. **忘了语法** → 顶部菜单栏 **帮助 → 搜索语法速查**。
   那一页是**按「我想找什么」列的写法清单**（不用记字段名），
   每条写法**点一下就填进搜索框**。
   想知道「引擎到底支持哪些字段」，同一面板里切到 **⌘/**（帮助中心）的
   「完整语法表」那一页；想通读全部用法，看 **帮助 → 完整手册**（就是这一本）。

**标题栏**（从左到右）

| 位置 | 是什么 | 怎么用 |
|---|---|---|
| 放大镜图标 | 搜索框 | 打字就搜。里面会**给语法上色**：字段和修饰符都是**蓝色**、运算符**橙色**、字符串**绿色**、路径**青色**、`NOT` **红色** |
| 刷新 | 重新扫描索引 | 新建/删了文件后按它。扫完自动重搜一次 |
| 收藏 | 收藏当前搜索条件 | 再点一次取消。收藏了会变成蓝色 |
| 设置 | 索引目录等 | 打开「设置」抽屉 |

**结果表**（中间那块）

- 列有 **名称 / 位置 / 大小 / 修改时间**。
- **点表头**换排序：点「名称」「大小」「修改时间」都行；**再点一次同一个表头**就翻方向
  （↑ 变 ↓）。
- 「位置」列显示的是**所在目录**，不是完整路径。
- 排序是**升序时目录排在前面**，所以中间会插一条分隔行（写着「文件 (9)」）；
  降序时反过来，分隔行写「文件夹 (3)」。

**状态栏**（最下面那条）

- 左边：命中数「N 项（文件 X · 目录 Y）」。
  **如果查询里有引擎不认识的字段**，这里会直接显示那句警告（比如
  「未知字段 name:（引擎支持 ext / size / dm / path / folder / regex 等）」）。
- 右边：索引状态（正在扫描 / 已索引 N 项）、索引失败原因、这次搜索耗时。

**浮层**（盖在结果表上面的东西，同一时刻只会开一个）

| 怎么打开 | 是什么 |
|---|---|
| 在结果行上**右键** | 右键菜单：打开 / 在访达中显示 / 收藏此文件（或此目录）/ 详情 |
| 右键菜单里点 **详情** | 预览卡：文件名、所在目录、大小、修改时间、类型 + 三个按钮 |
| **⌘/** | 帮助中心（默认停在「语法速查」那一页） |
| **⌘B** | 书签与最近面板 |
| 菜单栏 **帮助 → 搜索语法速查** | 帮助中心的速查页（按「我想找什么」列的写法清单） |
| 菜单栏 **帮助 → 完整手册** | 帮助中心的手册页，就是这一本 |
| 标题栏 **设置** | 设置抽屉 |

**任何面板都能用 Esc 关掉**，也可以点抽屉外面的暗色区域关掉。

## 搜索

### 基本搜索

- **打字就搜**，停 120 毫秒就出结果，不用按回车。
- **按回车 = 提交**。提交过的查询会进「最近搜索」（⌘B 面板里能看到）。
  只是打字没提交的话**不会**进最近列表 —— 否则每敲一个字符就多一条，全是垃圾。
- **默认匹配的是文件名**，不是路径。想连路径一起搜要加 `path:`（见下）。
- **默认不区分大小写**：`ALPHA` 能搜到 `alpha.txt`。要区分就写 `case:`。
- **空查询 = 0 条**。空白字符也一样（连打几个空格也是 0 条）。
  想「把所有东西都列出来」用 `*`。
- 搜出来的东西**按文件名排序**（不是按相关度）。想按大小/时间排，点表头。

### 搜索语法速查

> **不想记语法？** 用 **帮助 → 搜索语法速查**（或 **⌘/**）——
> 那一页是**按「我想找什么」组织**的写法清单，每条**点一下就填进搜索框**，
> 还有一栏「容易踩的坑」列出那些**写错了不会报错、结果却是错的**的写法。
> 下面这一节是**完整**的语法表（按语法分类），适合通读与查阅。

**下面这三张表是完整的** —— 引擎认识的每一个修饰符、每一个函数字段、每一个运算符
都在里面。引擎那边加了新东西，这里会跟着变（有一道自动测试盯着）。

#### 修饰符（15 个）

修饰符的写法是 `修饰符:值` —— 冒号后面跟**它要修饰的那个词**。
`file:alpha` = 「在 alpha 里，只要文件」。它也能修饰字段：`file:size:>10M`。

| 写法 | 作用 | 例子 |
|---|---|---|
| `case:` | 区分大小写 | `case:ALPHA` |
| `nocase:` | 不区分大小写（默认就是，这个是显式写出来） | `nocase:ALPHA` |
| `exact:` | 完全匹配，不是子串 | `exact:alpha.txt` |
| `file:` / `files:` | 只要文件 | `file:alpha` |
| `nofileonly:` / `nofilesonly:` | 取消「只要文件」 | `nofileonly:alpha` |
| `folder:` / `folders:` | 只要目录 | `folder:Downloads` |
| `nofolderonly:` / `nofoldersonly:` | 取消「只要目录」 | `nofolderonly:Downloads` |
| `path:` | 连**完整路径**一起匹配 | `path:Documents` |
| `nopath:` | 只匹配文件名（默认行为，显式写出来） | `nopath:Documents` |
| `regex:` | 开启正则 | `regex:"^gam"` |
| `noregex:` | 关闭正则 | `noregex:alpha` |

> ⚠️ **`file:` / `folder:` 是「整个查询」的开关**，不是只作用于紧跟的那一个词。
> 写了 `file:` 之后，这条查询就只可能命中文件 —— `nofileonly:` / `nofilesonly:`
> 做的正是**把它关掉**（`nofolderonly:` / `nofoldersonly:` 同理）。
>
> 例：`nofileonly:报告` = 在**文件和目录**里找「报告」。

#### 函数字段（18 个）

字段的写法是 `字段:值`。

| 写法 | 作用 | 例子 |
|---|---|---|
| `ext:` | 按扩展名。多个用**分号**隔开 | `ext:pdf;md` |
| `size:` | 按字节大小 | `size:>10M` |
| `dm:` / `datemodified:` | 按修改时间 | `dm:2024-01-01` |
| `contenttype:` | 按 MIME 类型（text / image / video / audio / pdf…） | `contenttype:text` |
| `parent:` | 直属父目录是它的那一层 | `parent:/Users/me/Downloads` |
| `depth:` / `parents:` | 目录深度（索引根算 0 层） | `depth:0` |
| `empty:` | 空目录 | `empty:` |
| `childcount:` | 子项总数（文件 + 目录） | `childcount:1` |
| `childfilecount:` | 子文件数 | `childfilecount:1` |
| `childfoldercount:` | 子目录数 | `childfoldercount:0` |
| `app:` | 应用（内置宏） | `app:` |
| `archive:` | 压缩包（内置宏） | `archive:` |
| `audio:` | 音频（内置宏） | `audio:` |
| `doc:` | 文档（内置宏） | `doc:` |
| `pic:` | 图片（内置宏） | `pic:` |
| `video:` | 视频（内置宏） | `video:` |

#### 运算符（15 个）

| 写法 | 作用 | 例子 |
|---|---|---|
| 空格 | 隐式 AND（等同于 `AND`） | `alpha beta` |
| `AND` / `&&` | 两个条件都要满足 | `alpha AND beta` |
| `OR` / `||` | 满足其中一个 | `alpha OR beta` |
| `NOT` / `!` | 取反（只作用于紧跟的那一个） | `NOT ext:png` |
| `(` `)` | 分组 | `(alpha OR beta) AND txt` |
| `:` | 字段和值之间的连接符 | `ext:pdf` |
| `=` | 等于 | `size:=2000` |
| `<` | 小于 | `size:<10M` |
| `<=` | 小于等于 | `size:<=10M` |
| `>` | 大于 | `size:>10M` |
| `>=` | 大于等于 | `size:>=10M` |
| `..` | 区间，**两端都含** | `size:1000..3000` |

> ⚠️ **`AND` / `OR` / `NOT` 必须大写。**
>
> 引擎是**逐字符精确比对**的（`strcmp`），所以小写的 `not ext:png`
> 会被当成**搜文件名里有 "not" 这个词** —— 不报错，只是结果完全不对。
>
> 不想大写就用符号：`&&` `||` `!`（等价，且不受大小写影响）。
> `!` 和 `NOT` 一样只作用于**紧跟的那一个**。

> ℹ️ **查询写到一半不会报错。**
> 引擎对「还没写完」的查询是**能搜多少搜多少**：已经写好的条件照常生效
> （`alpha AND` 仍然显示 alpha 的结果），状态栏左下角会提示
> 「AND 后面还没有条件（还没写完）」。
> 括号没闭合、逻辑词后面还没写东西，也都是这样 —— 不会弹错误。

#### 另外两个不是「token」但很好用

| 写法 | 作用 | 例子 |
|---|---|---|
| `*` | 零个或多个字符 | `*.pdf` |
| `?` | 正好一个字符 | `k?ng` |

`"..."`（双引号）里的内容**当字面量**处理，空格也不拆词。
反斜杠 `\` 用来转义下一个字符。

### 语法详解

#### 逻辑怎么组合

```
alpha                    文件名里含 alpha
alpha beta               同时含 alpha 和 beta（空格 = AND）
alpha AND beta           同上
alpha OR beta            含 alpha 或者含 beta
NOT alpha                不含 alpha
!alpha                   同上
(alpha OR beta) AND txt  含 alpha 或 beta，且含 txt
```

`NOT` 只作用于**紧跟的那一个**。`NOT ext:pdf AND ext:md` =
「不是 pdf」**且**「是 md」—— 不是「不是 (pdf 且 md)」。

#### 扩展名

```
ext:pdf                  扩展名是 pdf
ext:pdf;md               扩展名是 pdf 或者 md（分号，不是逗号）
ext:                     扩展名是空的那些文件（少见）
```

**扩展名不区分大小写** —— `ext:PDF` 和 `ext:pdf` 是一回事。

#### 文件大小

```
size:>10M                大于 10 MB
size:>=10M               大于等于 10 MB
size:<10M                小于 10 MB
size:<=10M               小于等于 10 MB
size:=2000               正好 2000 字节
size:1000..3000          在 [1000, 3000] 里 —— 两端都含
```

**单位是十进制，不是二进制**：`1k` = 1000 字节，`1M` = 1 000 000 字节，`1G` = 10 亿字节。
可以带 `b`/`B`：`1kb`、`1MB` 都行。

**注意 `MiB` / `GiB` 这种写法是不行的** —— 引擎只认 `k / M / G / T`（可带 `b`），
写 `1MiB` 不会报错，只会**一条都搜不到**。

> ⚠️ **界面上的大小和查询里的大小不是一个口径**：
> 结果表把 2000 字节显示成「2.0 KB」（1024 进制），
> 但 `size:2k` 是 2000 字节（1000 进制）。想精确命中就按字节写，别照着界面上的 KB 抄。

#### 修改时间

```
dm:2024                 2024 年被改过的（2024-01-01 00:00:00 ~ 2025-01-01 00:00:00）
dm:2024-01              2024 年 1 月
dm:2024-01-01           2024 年 1 月 1 日那一天
dm:"2024-01-01 10:30"   精确到分钟（值里有空格，要加引号）
dm:>2020-01-01          2020-01-01 之后改的
dm:2024-01-01..2024-12-31   那一整年（**右端那天算进去**）
dm:2024..               2024 年之后（含 2024）
dm:..2024               2024 年之前（含 2024）
```

`dm:` 和 `datemodified:` 是同一个东西，写哪个都行。

> ⚠️ **日期区间的右端是【算进去】的**。
>
> `dm:2024-01-01..2024-01-31` 覆盖的是 **1 月 1 日到 1 月 31 日整天**。
> （数字区间也一样是两端都含：`size:1000..3000` 含 3000。）

#### 还能用「日期常量」（省得算具体日期）

除了上面那些写死的日期，`dm:` 还认这些**词**：

```
dm:today                今天这一天
dm:yesterday            昨天
dm:monday … dm:sunday   最近的那个星期几（缩写 dm:mon … dm:sun 也行）
dm:january … dm:december 最近的那个月（缩写 dm:jan … dm:dec 也行）
```

还有一类是「**前缀 + 数量 + 单位**」拼出来的：

```
dm:lastmonth            上个月（1 号到月末，整整一个月）
dm:pastmonth            过去一个月（从一个月前到今天）
dm:thisyear             今年年初到今天
dm:last3days            前 3 个完整的 day（不含今天）
dm:past3days            过去 3 天（含今天）
dm:oneday               一天前（= 昨天）
dm:dozendays            12 天前
dm:3minutes             3 分钟前
```

- **前缀**：`last` / `inthelast` / `past` / `previous` / `prev` / `this`
- **数量**：数字（`3`）或英文词（`one`…`ten`、`dozen`、`hundred`）
- **单位**：`year` `month` `week` `day` `hour` `minute` `min` `second` `sec`
  （数量 > 1 时单位要**加 s**：`days` `months`…）

> ⚠️ **日期常量里不能有空格 —— 一个都不能。**
>
> 引擎是把这段值**按空白切开**再解析的，所以 `dm:last 3 days` 会被切成
> `dm:last` 和 `3` 和 `days` 三段，前一段解析不出来，后两段变成普通的搜索词。
>
> **加引号也救不了**：`dm:"last 3 days"` 里的空格照样在，解析照样失败 ——
> 结果是**一条都搜不到，而且一声不吭**。
>
> ✅ 正确写法是**连起来写**：`dm:last3days` / `dm:pastmonth` / `dm:thisyear`。
> （这也是应用内「帮助 → 搜索语法速查」里列的写法。）
>
> 单个词的常量（`dm:today`、`dm:january`）本来就是连着的，不用管这条。

> `last` 和 `past` 不一样：`lastmonth` 指**上一个完整的月**（1 号到月末），
> `pastmonth` 指**从一个月前到今天**这一段。
> `last3days` 是**今天之前的 3 个整天**（不含今天），`past3days` 才含今天。

#### 路径

```
path:/Users/me/Docs     完整路径里含这一串
path:Documents          完整路径里含 Documents（子串匹配，不限位置）
path:~                  ← 搜不到任何东西，别用
```

**引擎不做 `~` 展开**。`path:~` 永远是 0 条，要写绝对路径 `path:/Users/me`。

路径是**子串匹配**：`path:Documents` 会把 `/Users/me/Documents/报告.docx` 和
`/Volumes/Data/Documents/旧` 都搜出来。

#### 目录结构

```
parent:/Users/me/Downloads   直属父目录就是它的那一层
depth:0                      索引根目录本身
depth:1                      根的下一层
parents:1                    和 depth:1 一样（同一个东西的别名）
empty:                       空目录
childcount:1                 正好 1 个子项（文件 + 目录）
childfilecount:1             正好 1 个子文件
childfoldercount:0           一个子目录都没有
```

计数类字段也支持**区间**：`childfilecount:2..5` = 「2 到 5 个子文件（含两端）」。

#### 内容类型

```
contenttype:text             所有文本类文件（text/*）
contenttype:image            所有图片
contenttype:video            所有视频
contenttype:pdf              单个类型（application/pdf）
```

按 **MIME 类型**筛。目录算 `directory`。
认不出来的扩展名一律当二进制（`application/octet-stream`）。

也认**内置的类型组名**：`contenttype:pic` = 所有图片，`contenttype:doc` = 所有文档。

#### 内置宏（6 个）

`app:` / `archive:` / `audio:` / `doc:` / `pic:` / `video:` 是引擎内置的
「一组扩展名」的简称 —— `pic:` 相当于一大串 `ext:jpg;png;gif;…`。

**冒号后面不要再写值**：写成 `pic:png` 的话，`png` 会被**忽略**
（引擎会给出警告），结果还是「所有图片」，不是「筛选 png」。
要按扩展名筛请用 `ext:png`。

> `app:` 能认出 **`.app` 应用包** —— macOS 上 `.app` 是**目录**，
> 引擎会按目录名里的扩展名来判断。

日常用 `ext:` 更直接，宏知道就行。

#### 正则

```
regex:"^gam"                以 gam 开头
regex:"\.pdf$"              以 .pdf 结尾
file:regex:".+\.pdf$"       所有以 .pdf 结尾的文件
```

- 正则靠 `regex:` 修饰符开启，**没有** `/.../` 这种写法。
- 正则里的特殊字符（`( ) \` 等）要转义。**整个正则用双引号包起来最省事**。
- 想匹配字面的点要写 `\.`。

#### 引号与转义

```
"my file.txt"        整个当一个字面量（空格不拆词）
"alpha.txt" OR "beta.md"
path:"nested/delta"  引号也能用在字段值里
```

反斜杠 `\` 用来转义下一个字符（空格、引号、反斜杠本身）：

```
/home/user/my\ folder
```

> ⚠️ **引号没闭合是个坑**：写 `"foo` 然后后面又跟了 `ext:`，
> 引擎会把后面全部吞成一个字面词 —— `ext:` 过滤**完全失效，而且一声不吭**。
> 查询框里看到光标还在引号里，先把引号补上再继续写。
> （⌘/ 语法面板发现引号没闭合时会拒绝追加并提示你。）

## 索引目录

**在哪改**：标题栏 **设置** → **索引目录** → **添加目录…** → 选目录 →
**应用并重建索引**。

- **留空 = 索引整个用户家目录**（`$HOME`）。
- 换了目录会**重新扫一遍**，扫完自动重搜一次。
- 目录非法（不存在 / 不是目录）会**报错，而且不动原来的索引** —— 不会把你现在的
  索引搞坏。
- 设置面板下面还列着**当前生效的排除规则**（来自引擎本身，只读）：

  ```
  /.snapshots
  /proc
  /sys
  */Library
  */Applications
  */.Spotlight-V100
  /System*
  /private/var*
  /cores*
  [hidden files and folders]
  ```

  也就是：**隐藏文件、`Library`、`Applications`、`/System`、`/private/var` 这些
  不会被索引**。所以「搜不到 Applications 里的东西」是正常的，不是坏了。
  这份规则**在界面里改不了**（引擎自己定的）。

**性能提示**

| 索引范围 | 感受 |
|---|---|
| 一个小目录（几百项） | 毫秒级，随便搜 |
| `$HOME`（8 千多项） | 建索引不到 1 秒，搜索几十毫秒 |
| 一整块硬盘 | 建索引几十秒到几分钟；**而且这条操作是同步的**，界面会卡在「正在扫描」 |

**索引目录设小一点，体验会好很多** —— 常用的地方建索引，冷门的地方临时用 `path:` 搜。

> 索引目录变了之后，**自动刷新**会跟着换监听对象（约 1 秒内，不用重启）。
> 同一节里还有一个 **「文件变化时自动刷新索引」** 开关 ——
> 什么时候该关，看「自动刷新索引」那一节。

## 自动刷新索引

**默认开着。** 被索引的目录里有文件新建 / 修改 / 删除时，应用会**自动重扫一遍索引**，
扫完**自动重搜一次** —— 你不用点刷新，新文件自己就出现在结果表里了。

- **在哪儿关**：标题栏 **设置** → **索引目录** → **文件变化时自动刷新索引** 开关。
  **开关立即生效**，不需要「应用并重建索引」，也不用重启应用。
- **只监听被索引的目录**。改了索引目录之后，监听会自动跟着换（约 1 秒内）。
- **有防抖，不会连着扫**：
  - 一次「保存」在系统看来是好几个事件（建临时文件 → 写内容 → 改名），
    所以要**安静 0.8 秒**才会真的扫一次 —— 一次保存只扫一次；
  - 两次自动重扫之间**至少隔 5 秒** —— 就算你（或别的程序）一直在改文件，
    也不会把机器刷爆。
- **只监听、不扫描的时候几乎不费 CPU**：实测空转 20 秒只用了 0.05 秒 CPU（约 0.25% 单核）。

> ⚠️ **索引整个家目录（`$HOME`）时建议把这个开关关掉**
>
> `$HOME` 有 8 千多项（排除规则挡掉了 `Library`、构建产物等），
> 扫一遍约 **0.3 秒**。而 `$HOME` 里**别的程序一直在写东西**
> （聊天软件的数据库、系统自己的缓存……），每写一次就可能触发一次全量重扫 ——
> 最多每隔 5 秒扫一次。
>
> 想省资源，两个办法挑一个：
> ① 把索引目录改小（只索引常用的几个地方）—— **推荐**；
> ② 保留 `$HOME` 但把「文件变化时自动刷新索引」关掉，改用 **刷新** 按钮。

## 刷新

**什么时候需要按**：你新建/删除/重命名了文件，但结果里还是旧的。

**先看自动刷新**：默认情况下不需要按 —— 应用会自己跟上（见上面的「自动刷新索引」）。
如果你把那个开关关掉了，或者改的是**没被索引**的目录，那就得按。

**怎么按**：标题栏的 **刷新** 按钮。按下去会：

1. 重新扫一遍索引目录（$HOME 量级大概 1~2 秒）；
2. 扫完自动重搜一次 —— 你不用再点搜索。

按钮在扫描期间会变成 **刷新中…** 并且点不动，防止连点。

> 换索引目录不用按刷新 —— 「应用并重建索引」自己就重扫了。
>
> 自动重扫和刷新按钮走的是**同一套逻辑**，所以两者的结果和状态栏显示是一样的。

## 后台常驻模式

Lodestar 可以在后台常驻 —— 关掉窗口它**不会退出**，随时能叫回来。

### 怎么唤起

| 方式 | 说明 |
|---|---|
| **全局快捷键** | 默认 `⌥⌘Space`。在任何软件里按它都能唤起。 |
| **菜单栏图标** | 屏幕右上角那个放大镜。**左键**唤起（如果窗口已经在前台，再点一下会收起）；**右键**弹出菜单（打开 Lodestar / 设置… / 退出）。 |
| **关闭按钮** | 点窗口左上角的红色按钮 —— 窗口收起来，程序继续在后台待命。 |
| **Dock 图标** | 点 Dock 里的 Lodestar 图标，窗口也会回来。 |

> 唤起后光标会自动落在搜索框里，上次的查询处于**选中**状态 ——
> 直接打字就是替换掉它。

### 后台时它占多少

> 下面的数字是**在这台机器上实测的**（2026-10-23，索引 `$HOME` 共 **8,134 项**）。
> CPU 用 `ps` 的 **CPU 时间增量 ÷ 墙钟**量（不是 `top` 那个开机以来的平均值 ——
> 那个会被刚才的一次补扫稀释掉，看不出空闲时的真实开销），
> **4 个进程合计**（主进程 + WebKit 的 GPU / 渲染 / 网络三个辅助进程）。

| | 收起来（后台常驻） | 窗口开着 |
|---|---|---|
| **CPU** | **0.04 %**（机器上别的程序不停写文件时约 **0.2 %**） | **0.6 ~ 1.4 %**（同样受那件事影响） |
| **内存** | 合计约 **100 MB** | 合计约 **110 MB** |
| 唤回 | 窗口从「看不见」到「真的在屏幕上」约 **30 毫秒**（应用侧） | — |

> **为什么后台几乎不烧 CPU**：窗口收起来之后，界面根本看不见，
> 那就没必要继续刷新状态栏 —— 应用会**主动停掉**状态轮询，
> 窗口一回来再重新开上。
> （顺带一提：窗口**开着**的时候，状态栏也不再每 0.8 秒重画一次 ——
> 只有内容真的变了才重画。）
>
> **「别的程序不停写文件」是什么意思**：Lodestar 盯着家目录的变化，
> 别的程序写得越勤，它要判断的「这次变化要不要进索引」就越多
> （那些判断本身很便宜，但量大了也会累积成零点几个百分点）。
> 典型来源：开发工具、虚拟机、聊天软件的缓存目录。
>
> 空闲判定：窗口收起来算空闲；窗口还开着但你切去别的 app 超过 **20 秒**也算。
> 空闲时会自动暂停「文件变化自动重扫」，你唤起它时会补扫一次（**只在真有变化要收时才扫**）。
>
> **唤起不一定会付一次全量重扫。** 「补扫」的目的是把空闲期间攒下的变化收进索引，
> 所以：
>
> - **空闲期间确实有文件变了** → 唤起时会补扫一次，
>   好让你**立刻**就能搜到空闲期间新建的文件；
> - **空闲期间什么都没变** → **不扫**（扫了结果和现在的索引一模一样，纯浪费）；
> - **那些变化已经被某次已完成的扫描收进去了**（比如你刚点过「刷新」）→
>   也**不扫**（再扫一遍是把同一批文件重新扫一次）。
>
> 实测（索引 `$HOME` 共 **8,134 项**）：一次全量重扫约 **276~310 毫秒** CPU。
> 所以「唤起 → 能搜到空闲期的新文件」这件事，
> 代价是**最多**一次几百毫秒的重扫，不是必然的。
>
> 走「点回焦点」那条路（窗口一直开着、只是切去别的 app）会更慢一点：
> 它靠文件变化的脏标志自然补扫，要等满 5 秒的最小间隔，约 **5 秒**后索引才跟上。

### 开机自启

设置 → 「开机时自动在后台驻留」打开即可。
登录之后 Lodestar 会在后台待命（**不会弹窗口**），按全局快捷键就能叫出来。

> 重新打开设置面板时开关会自己翻成「关」。

### 改快捷键

设置 → 「全局快捷键」→ 点「录制」→ 直接按下想要的组合键（**Esc** 取消）。
必须带修饰键（`⌘` / `⌥` / `⌃` / `⇧`）—— 纯字母键会和正常打字打架。

- 点「**清除**」就把全局快捷键整个关掉（之后只能靠菜单栏图标唤起）。

## 常见问题

**新建的文件没出现在结果里**

1. **「文件变化时自动刷新索引」开关被关掉了？** 设置 → 索引目录 里有那个开关。
2. 那个文件在**被索引的目录**里吗？只监听被索引的目录 —— 改索引目录后约 1 秒内跟上。
3. 刚改完的话**再等 0.8 秒** —— 防抖要安静 0.8 秒才扫（一次保存只扫一次，
   不是不扫）。
4. 它是不是**隐藏文件**、或在 `Library` / `Applications` 里？那些本来就不索引。
5. 索引的是 `$HOME`、机器又比较慢？全量重扫本身要 0.3 秒左右，
   大目录上「扫完 + 重搜完」可能要一秒出头。

**搜不到东西**

1. 索引还没建好？看状态栏是不是还写着「正在扫描索引…」。
2. 那个东西在被排除的目录里？（`Applications`、`Library`、隐藏文件 —— 见上面的排除规则）
3. 查询里有没有**没闭合的引号**？那会把后面的内容全吞掉，而且不报错。
4. 字段名拼错了？状态栏左下角会显示「未知字段 xxx:」——
   引擎支持的字段就是速查表里那些。

**查询还没写完会不会报错**

不会。引擎把「还没写完」和「写错了」分开处理：

- **还没写完**（`alpha AND`、单独一个 `(`、括号没闭合）→
  **已经写好的条件照常出结果**，状态栏提示一句「还没写完」。
- **写错了**（字段名拼错、大小写看不懂）→ 状态栏明确说是哪里看不懂。

**搜出来一堆没用的**

- 加 `ext:` 限死类型：`ext:pdf`
- 加 `file:` 只要文件：`file:ext:pdf`
- 路径里那个词太常见？换成更具体的一段：`path:/Users/me/Docs`

**`path:~` 为什么搜不到**

引擎不展开 `~`。写绝对路径 `path:/Users/me`。

**结果表里的大小和 `size:` 对不上**

界面是 1024 进制（2000 字节显示成 2.0 KB），`size:` 是 1000 进制
（`size:2k` 就是 2000 字节）。**要精确命中就按字节写。**

**索引不全 / 少了某个目录**

检查设置面板里的排除规则。`Applications`、`Library`、隐藏文件本来就不索引。

**改了设置，重启后没了**

设置存在
`~/Library/Application Support/com.lodestar.macos/settings.json`。
**别在应用运行时手改这个文件** —— 应用会整体覆盖它。改设置就用界面。

**双击 .app 打不开 / 提示「无法验证开发者」**

打包用的是 ad-hoc 签名（没有 Developer ID）。第一次打开要
**右键 → 打开** → 在弹窗里再点一次「打开」。

**打开是白屏**

那说明前端没嵌进二进制。开发时用 `pnpm --dir=app tauri dev`，
打包用 `bash app/scripts/bundle-app.sh`（别直接 `pnpm tauri build`）。

**面板按 ⌘/ 没反应**

焦点不在应用窗口里 —— 先点一下窗口。

## 已知限制

- **索引不是实时的，是「自动跟上」**。文件变了会自动重扫（默认开），
  但要等 0.8 秒的防抖，而且重扫是**全量**的（增量更新正在做，见下）。
- **索引 `$HOME` 且有别的程序在持续写文件时，自动刷新会明显吃 CPU**
  （最多每 5 秒一次全量重扫）—— 这种场景建议关掉开关，或者把索引目录改小。
- **`.DS_Store` 这类元数据变化也会触发一次全量重扫**（macOS 自己往目录里写
  `.DS_Store` 时）。行为是对的（目录真的变了），只是多扫一次。
- **排除规则改不了**。隐藏文件、`Library`、`Applications` 这些是引擎自己定的。
- **没有命令面板**（⌘K）。想找功能就翻这一本手册。
- **只有一个窗口**，没有多窗口、没有多标签页。
- **`path:` 不做 `~` 展开**。
- **正则没有 `/.../` 写法**，必须用 `regex:` 修饰符。
- **`size:` 只认 `k / M / G / T`（可带 `b`）**，`MiB` / `GiB` 不认（不报错，直接搜不到）。
- **打包出来的 .app 依赖 Homebrew 的那套库**（glib / pango / icu 等），
  换台没装的机器跑不起来。
- **排序偏好和列表种类偏好**在设置文件里存着，但界面还没用上 ——
  现在的排序是每次现点的，列表种类固定是「全部」。
